# مواصفة تصميم — الحلقة اليومية (Daily Loop)

**التاريخ:** 2026-11-02
**الحالة:** معتمد للتنفيذ (Design approved) — نسخة معدّلة بعد المراجعة (انظر سجل التعديلات في القسم 21)
**النطاق:** الشريحة الأولى من منصة إدارة الحضانات (Kidara)
**اللغة:** عربي فقط (RTL)

---

## 1. الملخص التنفيذي

Kidara منصة SaaS متعددة الحضانات (multi-tenant). الشريحة الأولى الموصوفة هنا هي **الحلقة اليومية**: هوية الطفل، تسجيله في حضانة، حضوره واستلامه، تقريره اليومي، سجله الصحي، تقييمه الشهري، وتقويمه في **جواز الطفل** القابل للمشاركة.

الهدف من الشريحة ليس إدارة الحضانة بالكامل، بل إثبات الحلقة التي تبني الثقة:

> **الحضانة تسجّل → ولي الأمر يشوف فوراً → السجل يتراكم → يصبح دليلاً قابلاً للنقل**

بقية الأنظمة (المالية، HR، CRM، الكانتين) مؤجلة بوعي إلى شرائح لاحقة، لكن قرارات الهوية والعزل هنا مصممة لتستقبلها.

---

## 2. المشكلة والرؤية

### 2.1 المشكلة
في السوق المستهدف، الحضانات تعمل بخليط من واتساب، دفاتر ورقية، وإيصالات كاش. النتيجة:

- ولي الأمر لا يملك سجلاً موثّقاً ليوم طفله، ولا دليلاً على ما حدث عند أي خلاف.
- صاحب الحضانة لا يستطيع المتابعة عن بعد ولا يملك بيانات تاريخية.
- الطفل ينتقل بين الحضانات ويبدأ من الصفر في كل مرة.
- استلام الطفل يعتمد على المعرفة الشخصية، وليس على تحقق موثّق.

### 2.2 الرؤية
هوية الطفل ملك ولي الأمر وليست ملك الحضانة. الحضانة تملك **التسجيل** والتقارير التفصيلية. مع تراكم البيانات المعتمدة، يتكوّن **جواز طفل** يمكن مشاركته بموافقة صريحة مع حضانة جديدة أو مدرسة لاحقاً.

### 2.3 مبادئ التصميم
1. **الثقة تحتاج دليلاً، لا كلاماً.** كل حدث حساس يُسجَّل بشكل غير قابل للتعديل.
2. **المعلمة هي عنق الزجاجة.** أي شاشة تزيد عن ٣٠ ثانية للطفل ستُهمَل.
3. **لا نطلب بيانات لا نحتاجها.** أقل قدر ممكن من البيانات الشخصية، وأقل صلاحية ممكنة.
4. **الشفافية متبادلة.** ولي الأمر يرى ما يخصه فقط؛ والحضانة ترى ما تحتاجه للرعاية فقط.
5. **الحضانة لا تحكم في الحضانة.** السيستم يسجّل قرارات الحضانة ولا يتخذ مواقف قانونية.

## 3. المستخدمون والأدوار

| الدور | النطاق | المسؤولية |
|---|---|---|
| `super_admin` | المنصة | إدارة الحضانات، الاشتراكات، إعدادات المنصة |
| `moderator` | المنصة | حسابات تجريبية، دعم، تفعيل/تعطيل حضانات |
| `owner` | حضانة | ملكية الحضانة، كل التقارير والإعدادات والمالية لاحقاً |
| `manager` | حضانة | إدارة يومية، اعتماد التقارير والتقييمات، قرارات التسجيل |
| `reception` | حضانة | تسجيل الحضور/الانصراف، إدارة الطلبات والمستلمين |
| `teacher` | فصل | كتابة تقرير اليوم، ملاحظات صحية، مسودة التقييم |
| `guardian_primary` | طفل | ملكية هوية الطفل، الصلاحيات الكاملة، إدارة الأولياء الآخرين |
| `guardian_secondary` | طفل | صلاحيات محددة يمنحها الولي الأساسي |

**ملاحظات على الأدوار:**
- نطاق المعلمة («فصله فقط») يُحدَّد بجدول `classroom_staff` وليس بالدور وحده.
- المستخدم الواحد قد يحمل أكثر من سياق (موظف في أكثر من حضانة، أو موظف وولي أمر في الوقت نفسه). الدور يُحسب لكل طلب بحسب سياقه (حضانة / ولي أمر)، وليس على مستوى الحساب.

### 3.1 صلاحيات ولي الأمر (قابلة للتفعيل لكل رابط)

| القدرة | الوصف | الافتراضي للأساسي |
|---|---|---|
| `view_reports` | التقرير اليومي والتقييمات | نعم |
| `view_health` | السجل الصحي والإصابات | نعم |
| `pickup` | إنشاء تصاريح الاستلام | نعم |
| `pay` | الفواتير والمدفوعات (شريحة لاحقة) | نعم |
| `manage` | إضافة/إزالة أولياء، تعديل بيانات الطفل | نعم |

الولي الأساسي فقط يملك `manage`. الأولياء الثانويون لا يستطيعون تعديل بيانات الطفل أو إدارة الآخرين.

## 5. المعمارية

### 5.1 العزل
- قاعدة بيانات واحدة، schema واحد.
- `nursery_id` على كل جدول تشغيلي.
- **Row-Level Security** في PostgreSQL كخط دفاع ثانٍ، بالإضافة إلى طبقة وصول بيانات تفرض العزل.
- دور قاعدة البيانات الذي يستخدمه التطبيق **ليس مالك الجداول** وبدون `BYPASSRLS`، وتُفعَّل `FORCE ROW LEVEL SECURITY`؛ وإلا تُتجاهل السياسات بصمت.
- **مساران للوصول بسياستين منفصلتين:**
  - **مسار الحضانة:** سياسة على `nursery_id`.
  - **مسار ولي الأمر:** سياسة على `child_id` عبر `guardian_links` النشطة والقدرة المطلوبة، لأن الأب قد يقرأ بيانات طفله عبر أكثر من حضانة (طفل منقول أو في حضانتين).
- السبب: مئات الحضانات، وليس آلافاً؛ التكلفة والتعقيد أقل. عند التوسع، تُنقل الحضانات الكبيرة إلى schema مستقل دون تغيير الكود.

### 5.2 الحدود العالمية والمحلية

**عالمي — مملوك لولي الأمر:**
`users`, `user_profiles`, `children`, `guardian_links`, `guardian_credentials`, `consents`, `passport_shares`

**محلي — مملوك للحضانة:**
`nurseries`, `classrooms`, `staff`, `classroom_staff`, `enrollments`, `attendance_events`, `pickup_passes`, `pickup_pass_children`, `daily_sheets`, `daily_comments`, `health_profiles`, `incidents`, `assessments`, `calendar_events`

**قاعدة ذهبية:** الحضانة لا تملك الطفل، تملك `enrollment`. انتقال الطفل يعني إغلاق تسجيل وفتح آخر، لا حذف هوية.

### 5.3 الوحدات (Bounded Contexts)

| الوحدة | المسؤولية | لا تفعل |
|---|---|---|
| `identity` | حسابات، جلسات، OTP، أدوار | لا تعرف شيئاً عن التقارير |
| `tenancy` | حضانات، اشتراكات، moderators | لا تصل لبيانات الأطفال |
| `children` | هوية الطفل، الأولياء، الموافقات، الجواز | لا تكتب تقارير يومية |
| `enrollment` | طلب، موافقة، تنشيط، انسحاب، نقل | لا تدير الحضور |
| `attendance` | دخول/خروج، تصاريح الاستلام | لا تعدّل هوية الطفل |
| `daily` | ورقة اليوم، الاستثناءات، التعليقات | لا تنشر بدون اعتماد عند الحاجة |
| `health` | حساسية، أدوية، إصابات، إقرارات | لا تظهر لغير المصرح لهم |
| `assessment` | محاور، مسودات، اعتماد، نشر | لا تُشارك تلقائياً |
| `calendar` | أنشطة ورحلات | — |
| `notifications` | اشتراك Push، قوالب، سجل تسليم | لا تفرض قواعد عمل |
| `audit` | سجل غير قابل للتعديل | لا يُحذف |

كل وحدة تتواصل عبر خدمات تطبيقية. لا وحدة تكتب في جداول وحدة أخرى. الأحداث البينية عبر **outbox table** (معاملات آمنة + معالجة موثوقة).

### 5.4 الستاك التقني (معتمد)
- **الـ API:** NestJS 11 + TypeScript
- **الواجهة:** React 19 + TypeScript + Vite + React Router + TanStack Query
- **التصميم:** Tailwind CSS + shadcn/ui مع دعم RTL
- **PWA:** `vite-plugin-pwa` + Workbox
- **قاعدة البيانات:** PostgreSQL + Prisma ORM + RLS
- **الطوابير:** Redis + BullMQ (إشعارات، مهام مؤجلة، إعادة محاولة)
- **التحقق:** Zod + `nestjs-zod` (عقد واحد بين الـ API والواجهة)
- **المصادقة:** JWT (access قصير + refresh مُدوَّر) + argon2 + OTP
- **التخزين:** S3-compatible (مستندات التحقق)
- **Push:** `web-push` + VAPID
- **الاستضافة:** Docker على VPS أو managed Postgres/Redis

**ملاحظات تنفيذية:**
- RLS تُفعَّل بـ `SET LOCAL app.current_nursery_id` (مسار الحضانة) أو `SET LOCAL app.current_user_id` (مسار ولي الأمر) داخل كل معاملة، وPrisma extension يمنع أي استعلام بدون أحد السياقين.
- الـ monorepo: `apps/api` (NestJS) + `apps/web` (React) + `packages/shared` (أنواع Zod المشتركة).
- الـ shared package يمنع انحراف الـ API عن الواجهة — أي تغيير في العقد يظهر كخطأ TypeScript.

السبب: TypeScript من الطرف للطرف، حدود وحدات واضحة في NestJS، وPWA أولاً بدون تعقيد SSR.

## 6. نموذج البيانات

### 6.1 عالمي

**`users`**
- `id` uuid
- `phone_e164` unique
- `password_hash` (nullable لو OTP فقط)
- `phone_verified_at`
- `status` (`active`, `suspended`, `deleted`)
- `created_at`, `last_login_at`

**`user_profiles`**
- `user_id`
- `full_name`
- `national_id_enc` (AES-256-GCM)
- `national_id_hash` unique (HMAC-SHA256 بمفتاح منفصل)
- `birth_date`
- `avatar_url`

**`children`**
- `id` uuid
- `full_name`
- `national_id_enc` + `national_id_hash` unique
- `birth_date`, `gender`
- `created_by_user_id`
- `origin` (`guardian`, `nursery_import`)، `claimed_at`
- `verification_status` (`unverified`, `verified`, `rejected`)
- `verified_by_nursery_id`, `verified_at`

**قاعدة:** `verification_status` هو توثيق الهوية **العالمية** فقط، ويحكم الجواز والمشاركة بين الحضانات. لا يمنع العمل اليومي داخل حضانة صدّقت على الطفل في `enrollment` (انظر F1/F2).

**`guardian_links`**
- `id`
- `child_id`, `user_id`
- `relation` (`father`, `mother`, `grandparent`, `other`)
- `is_primary` boolean
- `capabilities` jsonb (`view_reports`, `view_health`, `pickup`, `pay`, `manage`)
- `status` (`invited`, `active`, `revoked`)
- `restricted` boolean + `restriction_reason` + `restriction_document_ref`
- unique(`child_id`, `user_id`)

**`consents`**
- `id`, `child_id`, `user_id`
- `type` (`privacy`, `data_sharing`, `passport_share`)
- `scope` jsonb
- `version`, `granted_at`, `revoked_at`

**`passport_shares`**
- `id`, `child_id`, `created_by_user_id`
- `token_hash` (256-bit)
- `scope` jsonb
- `expires_at`, `revoked_at`
- `access_count`, `last_accessed_at`

**`push_subscriptions`**
- `id`, `user_id`, `endpoint` unique, `keys` jsonb (p256dh, auth)
- `device_label`, `user_agent`
- `status` (`active`, `expired`, `revoked`)
- `created_at`, `last_used_at`

**`guardian_credentials`**
- `id`, `user_id`
- `token_hash` (128-bit)
- `status` (`active`, `revoked`), `rotated_at`
- QR دائم لولي الأمر للاستلام بنفسه؛ لا يعمل إلا مع `guardian_link` نشط وبقدرة `pickup` وغير `restricted` لذلك الطفل.

**`otp_codes`** (أو مزود خارجي)
- `phone_e164`, `code_hash`, `purpose` (`signup`, `login`, `invite`)
- `expires_at`, `attempts`, `consumed_at`

### 6.2 محلي

**`nurseries`**
- `id`, `name`, `slug`, `phone`, `address`, `timezone`
- `settings` jsonb (سياسة نشر السلوك، ساعات العمل، فترة التصريح)
- `status`, `subscription_id`

**`classrooms`**
- `id`, `nursery_id`, `name`
- `age_min_months`, `age_max_months`, `capacity`
- `template_key` (`infant`, `toddler`, `preschool`)

**`staff`**
- `id`, `nursery_id`, `user_id`
- `role` (`manager`, `reception`, `teacher`)
- `title`, `hired_at`, `status`
- unique(`nursery_id`, `user_id`)

**`classroom_staff`**
- `id`, `nursery_id`, `classroom_id`, `staff_id`
- `role_in_class` (`lead`, `assistant`, `substitute`)
- `starts_on`, `ends_on` nullable
- unique(`classroom_id`, `staff_id`, `starts_on`)

**قاعدة:** نطاق المعلمة = الفصول التي لها فيها سجل ساري في `classroom_staff` اليوم. المعلمة البديلة تُضاف بتاريخ بدء وانتهاء.

**`enrollments`**
- `id`, `nursery_id`, `child_id`, `classroom_id`
- `status` (`approved`, `active`, `withdrawn`, `transferred`)
- `start_date`, `end_date`
- `created_via` (`application`, `import`, `direct`)
- `approved_by_staff_id`, `approved_at`
- `attested_by_staff_id`, `attested_at` (تصديق الحضانة على بيانات الطفل في `import`/`direct`)

**قاعدة:** في `import`/`direct` تكون الموافقة هي تصديق الحضانة نفسها (`attested`)، ويظهر الطفل للمعلمات بمجرد تفعيل التسجيل دون انتظار الأب. `enrollment` لا يُنشأ إلا بعد الموافقة. الطلب نفسه يُسجَّل في `enrollment_applications`. ينتقل `approved → active` عند `start_date`.

**`enrollment_applications`**
- `id`, `nursery_id`, `child_id`, `guardian_user_id`
- `status` (`submitted`, `under_review`, `approved`, `rejected`, `withdrawn`)
- `requested_at`, `decided_by_staff_id`, `decided_at`, `decision_note`

**`attendance_events`** — append-only
- `id`, `nursery_id`, `enrollment_id`
- `type` (`check_in`, `check_out`)
- `occurred_at`, `recorded_at`
- `method` (`qr`, `manual`, `pin`, `guardian_qr`)
- `recorded_by_staff_id`
- `pickup_pass_id` nullable
- `reverses_event_id` nullable
- `reason` (إجباري للـ manual)
- unique(`nursery_id`, `idempotency_key`)

الفهارس: (`nursery_id`, `enrollment_id`, `occurred_at`), (`nursery_id`, `occurred_at`)

**`pickup_passes`**
- `id`, `nursery_id`
- `created_by_user_id`
- `receiver_name`, `receiver_phone`, `receiver_relation`
- `token_hash`, `pin_hash` (argon2)
- `valid_from`, `valid_until`
- `single_use` boolean default true
- `status` (`active`, `used`, `expired`, `revoked`)
- `used_at`, `used_by_staff_id`
- `receiver_id_checked` boolean (تأكيد الموظف أنه طابق هوية المستلم؛ إلزامي عند الاستخدام)

**`pickup_pass_children`**
- `pickup_pass_id`, `child_id`, `status` (`active`, `used`)
- تصريح واحد يغطي أكثر من طفل (الإخوة).

**`daily_sheets`**
- `id`, `nursery_id`, `enrollment_id`, `date`
- `attendance_status` (`present`, `absent`, `late`, `early_leave`)
- `meals` jsonb (قائمة وجبات + كمية)
- `nap` jsonb (بداية/نهاية/جودة)
- `toilet` jsonb (عدد المرات + نوع)
- `mood` (`happy`, `calm`, `tired`, `upset`)
- `behavior_note`
- `behavior_status` (`none`, `pending_review`, `approved`, `rejected`)
- `behavior_approved_by_staff_id`, `behavior_approved_at`
- `health_note`
- `status` (`draft`, `submitted`, `amended`)
- `submitted_by_staff_id`, `submitted_at`
- `amended_by_staff_id`, `amended_at`, `amend_reason`
- `version` integer
- unique(`enrollment_id`, `date`)

**قاعدة التعديل:** المعلمة تعدّل ورقة فصلها حتى نهاية يوم التقرير (بتوقيت الحضانة) بسبب مسجّل، وبعدها المدير فقط. كل تعديل بعد التسليم = `amended` + إصدار جديد + الفرق ظاهر للأب.

**قاعدة النشر:** `behavior_note` لا يظهر لولي الأمر إلا عند `behavior_status = approved`. عند التعديل بعد النشر، النسخة القديمة تبقى في `audit_events` والواجهة تعرض الفرق.

- `id`, `daily_sheet_id`, `author_user_id`
- `body`, `created_at`
- `visible_to_guardian` boolean

**`health_profiles`**

- `reported_by_staff_id`

**`assessments`**
- `id`, `nursery_id`, `child_id`

- `requires_consent` boolean + `consent_type` (`trip_permission`)
- `created_by_staff_id`

**قاعدة:** أي `trip` بتحتاج موافقة ولي الأمر. تُنشئ طلب موافقة لكل طفل في الفصل، وتظهر حالة الموافقة في شاشة الحدث.

**`notifications`**
- `id`, `user_id`, `nursery_id` nullable
- `type`, `payload` jsonb
- `channel` (`push`, `in_app`)
- `status` (`queued`, `sent`, `failed`, `read`)
- `sent_at`, `read_at`

**`audit_events`** — append-only
- `id`, `nursery_id` nullable
- `actor_user_id`, `actor_role`
- `entity_type`, `entity_id`, `action`
- `before` jsonb, `after` jsonb
- `ip`, `user_agent`, `created_at`

## 7. التدفقات

### F1 — ولي أمر جديد
1. تسجيل بالموبايل + OTP.
2. إضافة الطفل: الاسم، الرقم القومي، تاريخ الميلاد، صورة شهادة الميلاد.
3. اختيار حضانة → إرسال طلب انضمام.
4. الحضانة تراجع حضورياً: مطابقة الرقم القومي للطفل والأب مع شهادة الميلاد.
5. موافقة → تحديد فصل → `enrollment` نشط → `child.verification_status = verified`.
6. تسجيل الموافقات (خصوصية، مشاركة).

**قاعدة:** لا يظهر الطفل لأي معلمة قبل أن يكون له `enrollment` نشط معتمد من الحضانة، ولا تقارير ولا سجل صحي قبل ذلك. أما `verification_status` (توثيق الهوية العالمية) فلا يمنع العمل اليومي، ويحكم فقط الجواز والمشاركة بين الحضانات.

### F2 — أطفال موجودون (استيراد)
1. الحضانة تضيف الأطفال أو تستورد Excel.
2. النظام ينشئ `children` بحالة `unverified` (`origin = nursery_import`) + `guardian_links` بحالة `invited` + `enrollment` نشط بتصديق الحضانة (`attested`) ليظهر الأطفال للمعلمات فوراً.
3. رابط دعوة للأب لتفعيل الحساب ومطالبته بسجل طفله (claim، انظر F9).
4. بعد التفعيل والتحقق الحضوري → `verified` (يفتح الجواز والمشاركة فقط).
5. لو مفيش ولي أمر متاح → الحضانة تسجّل ولي أمر بديل مع مستند.

### F3 — الحضور والاستلام
**الدخول:**
1. الاستقبال/المعلمة تمسح QR الطفل.
2. `attendance_events` بـ `type=check_in` + `idempotency_key`.
3. إشعار فوري للأولياء المصرح لهم.

**الاستلام بواسطة ولي الأمر نفسه:**
1. يعرض QR الدائم (`guardian_credentials`) من التطبيق.
2. الاستقبال تمسحه: تحقق من `guardian_link` نشط + `pickup` + غير `restricted`.
3. `check_out` بـ `method = guardian_qr` + إشعار للأولياء الآخرين.

**الاستلام بتصريح (شخص آخر):**
1. ولي الأمر ينشئ تصريحاً مؤقتاً لطفل أو أكثر: اسم المستلم، الموبايل، الصلة، صلاحية زمنية (افتراضي: حتى نهاية اليوم)، PIN ٦ أرقام.
2. التطبيق يعرض **الرابط والـ PIN منفصلين** مع تنبيه لإرسالهما برسالتين منفصلتين عبر واتساب.
3. الاستقبال تمسح QR التصريح أو تدخل PIN، ثم **تطابق هوية المستلم بصرياً مع الاسم المعروض** وتؤكد ذلك (`receiver_id_checked`).
4. تحقق: التصريح نشط + داخل الوقت + غير مستخدم.
5. `check_out` + `pickup_pass.status = used`.
6. إشعار فوري للأولياء.

**الرفض:** تصريح منتهي/مستخدم/ملغي → رفض + تسجيل محاولة + تنبيه المدير.
**الاستلام اليدوي:** للمدير فقط، بسبب إجباري، ويُسجَّل كاستثناء في الـ audit.

### F4 — التقرير اليومي
1. المعلمة تفتح شاشة الفصل → «الكل حاضر».
2. تسجيل جماعي (وجبة، نوم، مزاج) ثم استثناءات فردية.
3. حفظ تلقائي مسودة كل ١٠ ثوانٍ أو عند الخروج.
4. «تسليم» → `status=submitted` → إشعار **واحد لكل فصل**.
5. بعد التسليم: المعلمة تعدّل حتى نهاية يوم التقرير بسبب مسجّل، وبعدها للمدير فقط؛ كل تعديل `status=amended` + إصدار جديد، والفرق ظاهر للأب.
6. ولي الأمر يعلّق → إشعار للمعلمة والمدير.

**سياسة النشر:** الحقائق (حضور/أكل/نوم) تظهر فوراً. `behavior_note` لا يظهر إلا بعد اعتماد المدير. الفرق بين النسخ يظهر لولي الأمر عند التعديل.

### F5 — الصحة والإصابات
1. الحساسية تظهر بالأحمر في شاشة الفصل.
2. أي إصابة → `incident` فوري: النوع، الشدة، الوصف، الإجراء، الشهود.
3. إشعار فوري للأولياء.
4. إقرار إطلاع من ولي الأمر → `acknowledged`.
5. بدون إقرار خلال ٢ ساعات → تصعيد للمدير.
6. `closed` بعد الإقرار أو انتهاء المتابعة.

### F6 — التقييم الشهري
1. المعلمة تكتب مسودة على المحاور الخمسة.
2. `submitted` → المدير يراجع.
3. `approved` → `published` → يظهر لولي الأمر.
4. رفض → يرجع `draft` مع ملاحظة.
5. ولي الأمر يعلّق فقط، لا يعدّل.
6. التقييم المنشور يدخل في الجواز.

### F7 — الجواز
1. ولي الأمر يفتح الجواز (شرطه: `child.verification_status = verified`) ويختار النطاق:
   - التقييمات المنشورة (افتراضي: نعم)
   - تاريخ التسجيل والحضور (افتراضي: نعم)
   - السجل الصحي (افتراضي: لا)
2. ينشئ رابط مشاركة صالح ٧ أيام.
3. المستلم يفتح الرابط → عرض للقراءة فقط + تسجيل وصول.
4. إلغاء فوري متاح في أي وقت.
5. عند انتهاء الصلاحية → الرابط ميت.

### F8 — النقل بين الحضانات
1. الحضانة القديمة: `enrollment → transferred` بتاريخ.
2. الطفل ولي الأمر يقدّم طلب انضمام جديد.
3. الحضانة الجديدة ترى: التقييمات المنشورة + تاريخ الحضور فقط (لو وافق ولي الأمر).
4. التقارير التفصيلية تبقى ملك الحضانة القديمة ولا تنتقل.

### F9 — مطالبة الأب بسجل مستورد / تكرار الرقم القومي
1. الأب المدعو يفتح رابط الدعوة، ويتحقق بـ OTP على الرقم المدعو، ثم يطالب بسجل الطفل (`claimed_at`) وتنتقل ملكيته إليه.
2. عند إضافة طفل برقم قومي موجود مسبقاً (`national_id_hash`): الرد دائماً عام («تعذّر إكمال الطلب، تواصل مع الحضانة») دون كشف أن الطفل مسجّل لدى جهة أخرى.
3. لو أنشأ الأب سجلاً مستقلاً وللحضانة سجل مستورد لنفس الطفل: المدير يرسل طلب دمج، وبعد موافقة الأب تُدمج التسجيلات تحت `child_id` واحد + audit.
4. لو الرقم القومي المستورد خاطئ: الأب يفتح اعتراضاً، يُوقَف ربط الرقم بالسجل العالمي حتى يراجعه المدير حضورياً.

## 11. الخصوصية والأمان

### 11.1 الرقم القومي
- تشفير AES-256-GCM في قاعدة البيانات.
- `hash` منفصل (HMAC-SHA256 بمفتاح منفصل) لفحص التكرار.
- عرض مقنّع افتراضي: `29***********12`.
- العرض الكامل: `owner` و`manager` فقط، وكل اطلاع يُسجَّل.
- التحقق الفعلي من شهادة الميلاد حضورياً في الحضانة. لا يوجد API حكومي، والنظام يوثّق مين راجع ومتى.
- الأرقام غير المصرية: رقم جواز السفر + رقم قومي لولي الأمر + مستند.

### 11.2 الرموز
- QR الطفل وQR ولي الأمر الدائم: token عشوائي ١٢٨-bit، مخزّن كـ hash، غير قابل للتخمين، وقابل للتدوير عند الفقد.
- QR/PIN التصريح: token ٢٥٦-bit + PIN ٦ أرقام بـ argon2. الرابط والـ PIN يُعرضان منفصلين، والتحقق البشري من هوية المستلم إلزامي عند الاستلام.
- روابط الجواز: token ٢٥٦-bit، انتهاء ٧ أيام، سجل وصول، إلغاء فوري.

### 11.3 الموافقات
- موافقة خصوصية عند التسجيل (إلزامية).
- موافقة مشاركة بيانات منفصلة عند إنشاء الجواز.
- إلغاء أي موافقة يوقف المشاركة فوراً.
- إلغاء الحساب → إخفاء هوية + الاحتفاظ بسجلات قانونية فقط.

### 11.4 الاحتفاظ (افتراضي، قابل للضبط)
| البيانات | المدة |
|---|---|
| تقارير يومية | ٣ سنوات |
| حضور | ٣ سنوات |
| إصابات | ٥ سنوات |
| تقييمات | مدة التسجيل + ٣ سنوات |
| سجل تدقيق | ٥ سنوات |
| رقم قومي | مدة التسجيل + المدة القانونية |
| صور شهادات الميلاد والمستندات | تُحذف بعد اكتمال التحقق (افتراضي ٣٠ يوماً) ويبقى سجل من راجع ومتى |

### 11.5 حدود الثقة
- المعلمة ترى فصلها فقط افتراضياً.
- الاستقبال يرى تنبيهات الحساسية دون تفاصيل طبية كاملة.
- المدير لا يرى بيانات الحضانات الأخرى.
- `super_admin` لا يرى بيانات أطفال افتراضياً؛ أي وصول مدعوم بمبرر ومسجّل.

### 11.6 حالة الوصاية
النظام لا يحكم في النزاعات. الحضانة تستطيع تعليم ولي أمر بأنه `restricted` (لا استلام، لا مشاهدة) بناءً على مستند رسمي. القرار وقائعه تُسجَّل، والسبب والمستند مرجعان.

### 11.7 الـ audit والحذف
- `before`/`after` في `audit_events` لا تحتويان قيماً حساسة خاماً: الرقم القومي، التفاصيل الصحية، نص التعليقات الحرة. تُخزَّن كقائمة `changed_fields` أو hash أو قيمة مقنّعة.
- عند إلغاء الموافقة أو حذف الحساب: يبقى `audit_events` بدون أي حقل شخصي مباشر (معرّفات مجهولة فقط)، ويُنصّ في سياسة الخصوصية على ما يبقى ولماذا.

### 11.8 الامتثال القانوني
بيانات الأطفال تُعامَل كبيانات حساسة. حسب فهمنا الحالي لقانون حماية البيانات الشخصية المصري (رقم ١٥١ لسنة ٢٠٢٠) قد يلزم ترخيص أو تصريح من الجهة المختصة، وتعيين مسؤول حماية بيانات، وتحديد متطلبات مكان تخزين البيانات. هذه نقطة **تحتاج مراجعة محامٍ متخصص قبل تشغيل بيانات حقيقية**، وهي شرط في بوابة الإطلاق. هذا النص ليس استشارة قانونية.

## 13. الأداء

- شاشة فصل ٢٠ طفل: تحميل < ١.٥ ثانية على 3G، تفاعل < ١٠٠ms.
- حفظ جماعي = **طلب واحد** batch.
- فهارس إلزامية: (`nursery_id`, `enrollment_id`, `occurred_at`)، (`nursery_id`, `date`)، (`child_id`, `status`).
- الاستعلامات على `audit_events` لا تدخل في المسارات الحرجة.
- الإشعارات تُعالَج خارج مسار الطلب (queue).

## 14. الاختبار

### 14.1 وحدات
- آلات الحالة كلها.
- حساب الصلاحيات (`capability` × `role` × `scope`).
- تشفير/فك تشفير الرقم القومي وفحص التكرار.

### 14.2 تكامل
- مسار التسجيل الكامل من OTP إلى `verified`.
- الاستلام بتصريح: نجاح، انتهاء، استخدام مزدوج، إلغاء.
- ظهور التقييم بعد الاعتماد فقط.
- عزل الحضانات: طلب بيانات حضانة أخرى يرجع 404 لا 403.
- مسار ولي الأمر: قراءة طفل واحد عبر حضانتين نجحت، وقراءة طفل ليس طفله فشلت (404)؛ ودور التطبيق لا يتجاوز RLS.

### 14.3 أمن
- IDOR على `child_id` و`enrollment_id`.
- تصريح منتهي / مستخدم مرتين.
- تزوير QR / إعادة استخدام token.
- وصول معلمة لطفل خارج فصلها.
- محاولات OTP مفرطة (rate limit).

### 14.4 E2E
سيناريو يوم كامل: استقبال → تقرير جماعي → تسليم → إشعار → تعليق أب → استلام بتصريح → إقرار إصابة.

### 14.5 اختبار قابلية الاستخدام
على مرحلتين، بـ ٣ معلمات على الأقل في كل مرة: (١) على نموذج تفاعلي **قبل كتابة أي كود للشاشة**؛ (٢) على الشاشة المبنية. زمن إكمال تقرير فصل ٢٠ طفلاً يجب أن يكون < ٥ دقائق. لو فشل أي منهما، يُعاد تصميم الشاشة قبل المتابعة.

## 16. ترتيب البناء

مبني من النتيجة للخلف: النتيجة المطلوبة **تجربة حقيقية** لحلقة واحدة، وأي شيء لا تحتاجه التجربة يتأخر.

**قبل التجربة (الحلقة الأساسية):**
0. نموذج تفاعلي + اختبار المعلمات.
1. `identity` + `children` + `tenancy` (بما فيها `classroom_staff`) — العزل بمساريه.
2. `enrollment` — الطلب، الاستيراد بتصديق الحضانة، الدعوات والـ claim.
3. `daily_sheets` + `daily_comments` + بانر الحساسية البسيط + العمل دون اتصال.
4. `notifications` — Push وصندوق الإشعارات.
5. `attendance` + `pickup_passes` + QR ولي الأمر.
6. **التجربة:** حضانة واحدة وفصل واحد، مع مراجعة قانونية سابقة.

**بعد التجربة (تُرتَّب حسب ما تُظهره):**
7. `health` + `incidents` كاملة.
8. `assessment` + `passport`.
9. `calendar`.

**ملاحظة:** خلال التجربة تستمر الحضانة في إجراء الإصابات المعتاد (ورقي/واتساب) ويُعلَن ذلك للأهالي، لأن `incidents` الكاملة تأتي بعدها.

كل خطوة تُسلَّم قابلة للاستخدام ومختبرة قبل التالية.

## 20. معايير القبول

1. ولي أمر يستطيع تسجيل طفل، إرسال طلب لحضانة، وتفعيل الحساب بعد التحقق.
2. حضانة تستطيع استيراد أطفال ودعوة أولياء أمورهم، ويظهر الأطفال للمعلمات فوراً دون انتظار تفعيل الأهالي.
3. استقبال يسجّل حضوراً بـ QR في أقل من ٣ ثوانٍ.
4. ولي أمر ينشئ تصريح استلام (لطفل أو أكثر) والاستقبال يستخدمه مرة واحدة فقط، ويستطيع ولي الأمر الاستلام بنفسه عبر QR دائم.
5. معلمة تسلّم تقرير فصل ٢٠ طفلاً في أقل من ٥ دقائق.
6. ولي أمر يشوف التقرير ويعلّق عليه.
7. إصابة تُسجَّل ويُطلَب إقرار ولي الأمر وتُتابَع حتى الإغلاق.
8. تقييم شهري لا يظهر قبل اعتماد المدير.
9. جواز طفل يُشارك برابط مؤقت وينتهي تلقائياً.
10. أي محاولة وصول غير مصرح بها ترجع 404 وتُسجَّل.
